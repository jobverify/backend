# JobVerify Reel renderer

Python 3.12, FFmpeg (libx264, AAC and libass) and FFprobe prepare one API-selected job per portrait Reel. Install `requirements.txt` and the Times New Roman / Georgia font families; run `node scripts/social-video-drafts.js` through the authorized GitHub workflow. The runner has no database, storage or Instagram credentials.

`render.py --claim claim.json --output render-directory` consumes the API-owned plan. Production always requests `en-IN-NeerjaNeural` narration and word timings from edge-tts. Narration failure fails the draft. Source strings are JSON data; subprocesses never use a shell. The role and metadata cards, burned captions, private SRT, JPEG cover and original quiet instrumental bed come from the API-owned plan, generated speech and the official employer icon available at render time. The v6 Reel is exactly 15 seconds. Original speech longer than 27 seconds fails; shorter speech is fitted into at most 14.4 seconds using pitch-preserving FFmpeg atempo when necessary. Word timings scale with the same tempo, preserving every spoken word and the full closing request. The API independently validates uploaded media.

Fonts resolve from Windows Fonts, the Linux `msttcorefonts` directory, macOS Fonts, or `SOCIAL_VIDEO_FONT_DIR`. The Ubuntu render workflow installs `ttf-mscorefonts-installer`; font binaries are read from the system and are not bundled in this repository.

For local tool locations, set `SOCIAL_VIDEO_FFMPEG`, `SOCIAL_VIDEO_FFPROBE`, or `SOCIAL_VIDEO_PYTHON`; the workflow uses tools on PATH. `python -m unittest discover -s scripts/social-video` checks layout, timings and input bounds. Set `SOCIAL_VIDEO_RENDER_INTEGRATION=1` to also render and probe a real media fixture. `--fixture-audio` plus `--fixture-words` explicitly inject offline test narration; the production coordinator never passes these options. Word timings are JSON rows `{text,offset,duration}` in seconds.

The output manifest records hashes, byte lengths, dimensions, codecs, duration, and runtime versions. The coordinator checks file paths and hashes, renews the claim every 45 seconds, uploads all three artifacts, then completes the package. A fenced lease cannot attach output. At most two jobs are processed sequentially in one workflow run.

Assets:

- `assets/jobverify-logo.png`: existing JobVerify brand asset, copied from the frontend public assets.
- `assets/NotoSans-Regular.ttf` and `assets/NotoSans-Bold.ttf`: Noto Sans, SIL Open Font License; license in `assets/OFL-NotoSans.txt`. Source: [notofonts/noto-fonts](https://github.com/notofonts/noto-fonts/tree/main/hinted/ttf/NotoSans).
- `assets/Anton-Regular.ttf`: Google Fonts Anton, SIL Open Font License; license in `assets/OFL-Anton.txt`. Source: [google/fonts](https://github.com/google/fonts/tree/main/ofl/anton).
- `assets/instrumental.wav`: original synthesized 24-second A-minor/F/C/G pad, 80 BPM, no samples. `compose_music.py` is its complete composition/source; generated music is dedicated to the public domain under CC0. It is mixed quietly beneath speech with fades.

See `docs/social-publishing.md` for deployment ordering, identities and activation. Rendering does not grant approval or create a delivery.

Template `jobverify-reel-v6` uses violet, teal, coral and blue scenes, a high-contrast reading panel, and a hiring-company badge on job-detail cards. The dedicated QR screen omits employer branding. The API binds the job's stored `companyDomain` to the hashed render plan. `branding.py` discovers raster icons from that official HTTPS site, retaining aspect ratio and colours; it never guesses a domain from a company name or uses an ATS vendor's logo. Downloads have public-IP DNS checks, same-employer redirects, an 18-second budget, a 1 MiB byte limit and a four-megapixel decode limit. Missing, unsupported or unavailable icons use company initials. Logo provenance and the original byte hash are recorded in the manifest; the hash or `initials` is included in renderer versions.

The final job card contains a QR code for the exact `https://www.jobverify.in/jobs/<jobId>` URL bound to the API plan. Both the coordinator and Python validate the job ID and QR destination. QR modules use integer pixels and a four-module quiet zone; this card has no camera drift. Its 840-pixel target produces an 820-pixel code for the standard job URL, larger than the preceding 697-pixel code; actual dimensions use whole modules. The company section and cartoon girl are absent from this screen. The QR stays visible for at least three seconds before the closing follow request. The caption retains its normal direct job link.

Narration joins the role, first location, job-seeker audience and experience into a complete sentence, for example: "Microsoft is hiring for Principal Apps AI Consultant in Bengaluru for full-time experienced job seekers with 10-15 years of experience." Missing fields omit their connectors; existing "of experience" suffixes are not repeated. Optional salary and then experience clauses are omitted only when necessary to stay within the narration budget. Narration says only the first location name, removing comma-separated state/country or bracketed location codes without changing stored job facts. Its final instructions are "Scan the QR code for full details and to apply. Follow JobVerify.in for more jobs." It does not say "Find this role on JobVerify". The voice pronounces the domain as "JobVerify dot in" while captions show the actual handle. The QR card starts by the timed scan instruction, moving earlier when needed to keep at least three seconds before the follow cue. On the final word "Follow", the 96-pixel header mark travels to the centre of the upper content area at (480, 760) and grows to 728 pixels over 0.85 seconds. Closing type fades in after the mark reaches the centre, keeping the moving mark clear of the text. The manifest records QR/follow/centre timings and the QR URL.

Layout `full-width-serif-gold-v1` uses a 620-pixel-tall job card, half the preceding card's height. The white panel spans the video from left edge to right edge, with bounds (0, 288) to (1079, 908). The panel can extend beneath Instagram controls while its text retains the safe content margins. Primary headings, company names and role titles use Times New Roman; subheadings, metadata details and captions use Georgia. Text shrinks before ordinary words are broken across lines. The employer logo, label and name remain fixed above the divider. Details occupy the card's right-hand column, with the 960-pixel-tall cartoon girl on the left from y=520 to y=1480. Type fits the compact card; exceptionally long optional values retain a visible ellipsis. The role is followed by one labelled card per available field and the QR. The original source facts remain unchanged.

Critical content stays to the left of x=904 and above y=1490, reserving space along the right and bottom for Instagram controls. These are conservative layout margins chosen for this template. Job captions appear beside the character; QR captions use the full content width below the enlarged code. The QR has its own screen with branding, scan guidance and the code, without the company section. The character fades out before the QR and closing request. The closing logo and text move higher into the same content area.

`assets/cartoon-girl.png` remains the original generated transparent asset. `assets/cartoon-girl-gold.png` is the built-in image-generation edit used by the renderer: its inner top is gold, with the violet blazer, pose and character preserved. The corresponding `.prompt.txt` files record the prompts and tool provenance. Placement trims transparent padding while preserving the character's aspect ratio. The girl also appears on the JPEG cover. The manifest records card bounds, character height, reserved content limits, the closing-logo centre, asset hash, narration tempo and last spoken word end.

Burned captions use white text, lime karaoke highlights, a dark outline and a short pop entrance. Groups contain up to two words. Georgia is measured at a nominal 144 pixels and the rendered size fits each cue inside its safe text column, preserving ordinary words intact. During the closing follow request, the large dedicated closing text replaces burned captions; the private SRT still includes every spoken word.

Install `requirements-test.txt` to enable independent QR decoding in local tests. Deploy the API and authorized runner together because both require the v6 plan. Existing approved assets and factual snapshots remain valid. A changed employer domain fences an in-progress render; refresh the draft before retrying it. Rendering does not post or approve a Reel.
