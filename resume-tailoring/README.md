# AI resume preparation and tailoring

The active worker in `resumePipeline.js` runs the pinned Qwen3-4B-Instruct-2507 Q4_K_M model locally with llama.cpp. It reads the original document, entered or confirmed profile evidence, and the actual Abey template code in `templates/abey-resume.tex`, then generates a complete candidate LaTeX document using that template. Tailoring also supplies the prepared base LaTeX and the saved job's candidate-facing requirements. The selected Abey format takes precedence over a legacy base document's layout. Supported experience can be rewritten, selected, and ordered for the job; job requirements never become unsupported candidate claims.

Generated LaTeX passes a strict preflight and is compiled into the published PDF by Tectonic inside an isolated Docker container. Compilation has no network, host mounts, credentials, writable root filesystem, or shell escape. The PDF and downloadable TeX come from the same validated generated document. Abey's letter geometry, centered contact header, ruled sections and resume entry macros are preserved, with readable text alongside its contact icons. Useful links appear inline with contacts, projects, activities or certifications. The worker never appends a Links section or generic Original link labels; new output containing them is sent for repair. Unused annotation-only references and mismatched placeholder contacts may be omitted, while visible contact and profile destinations remain protected.

LaTeX decoding uses the actual Abey preamble and supported document commands in `src/utils/resumeLatexFormat.js`. Preparation and repair receive its layout code and macros with the sample body omitted. The immutable preamble and any confidently identified source contact header are prefilled in the assistant context, and the model generates the remaining candidate body and closing document. Inference replaces the complete trusted template instruction block with a reference to that prefix, so the model reads the actual template once instead of processing it twice. Candidate and repair data and independent audit prompts remain intact. This avoids spending input tokens repeating the template and output tokens regenerating fixed template or contact bytes. The complete prefix plus exact generated body passes preflight and is compiled unchanged. New worker output must retain this preamble and centered header; generic legacy layouts remain readable but are rejected as new output.

For confidently structured base resumes, the worker derives finite source blocks that account for every original entry and logical bullet, merging PDF line wraps. The model still reads the complete original text, useful link recipes and actual Abey code, and generates one complete LaTeX document. The compact preparation prompt omits redundant derived indexes because the decoder already fixes the factual headers and source blocks. Ambiguous source structures retain the full protected-fact prompt and normal inference. Validation and the independent factual audit always use the full original evidence.

When the source name is identifiable, decoding uses one finite source-derived contact header before the first section, retaining the original headline, location and visible contacts. Entry links stay in their original blocks. Confident base blocks preserve the source wording, exact headers, grades, dates, tools, categories and bullet order. An Education entry with no description closes without a fabricated item list. Course lists use columns when useful. Item-list spacing is compact enough for the Abey layout while text remains at least nominal 10pt. Long entries can continue in closed item lists across a page break without repeating their header. Every useful non-header link must resolve to one covered source unit, including links within skill categories; otherwise the worker keeps normal inference.

Generation explicitly disables optional thinking and uses temperature 0.7, top-p 0.8, top-k 20, min-p 0 and presence penalty 1.5 to reduce repetitive output, following the [Qwen non-thinking sampling guidance](https://huggingface.co/Qwen/Qwen3-4B-Instruct-2507#best-practices). The independent JSON factual audit remains at temperature zero. Its evidence summary is bounded to 512 characters, reserving the output budget for missing facts and unsupported claims; the full source and candidate remain in its input. Smaller models must pass the same source, compilation, pagination and factual checks before replacing the pinned model.

For dense base resumes, three-or-more-page inputs permit concise rewriting in structured narrative item slots from the first attempt. Fixed source headers, item counts, skill/certification text and useful links remain constrained. Narrative slots cannot emit lists, environments, headings or hyperlinks. Whole-source PDF fidelity and independent semantic comparison remain mandatory. In the preservation path, page breaks occur between closed finite source blocks and small optional positive spacers balance the pages.

When the compiled document passes deterministic factual checks but misses its physical page target, its single repair uses a short layout-only JSON request instead of regenerating the whole document. The model selects compact/original spacing and an enumerated safe break location using bounded, anonymous layout measurements. Its response is limited to 128 tokens. Trusted edits remove obsolete breaks, optionally reduce positive gaps and item-list spacing, and insert the selected break between closed lists. Long bullet lists can continue without repeating their heading. The candidate wording, inline links, contact header, template preamble, fonts and margins remain intact. Repaired LaTeX is validated and compiled again; the PDF must meet its page target and pass the full factual audit before publication. A failed layout correction never triggers a second full generation. Other validation failures retain the single document repair, with concise narrative slots available for overflowing base resumes when necessary.

Generation reserves up to five minutes for compilation, inspection and independent factual comparison. Before either kind of repair, the worker estimates its input/output cost using measured prefill/decode rates with conservative CPU defaults. A repair that cannot fit is rejected before inference, preserving the previous successful version. Public diagnostics record only allowlisted policy `abey-pagination-v2`, base/tailored mode, repair kind and bounded counters. Actions also logs its checked-out commit SHA so the deployed worker can be distinguished from an older workflow; the immutable dependency cache is independent of worker source revisions.

For tailored resumes and sources without a confident preservation plan, list macros and explicit environments have paired grammar rules, so sections occur outside those blocks. Actual recognized source sections occur once in their original order. Plausible undated headings from original source rows remain eligible as additional sections. Names, dated entry rows, bullet text and comma-separated skills cannot become optional section headings. Eligibility is checked before adding uppercase aliases. Confident plain-bullet coursework, certification and language sections use one list bounded by their original logical bullet counts; inline-only item content prevents nested lists bypassing that limit. Mixed heading/prose sections and very fragmented sources retain flexible choices. Known two-page targets require one explicit page break outside lists; known one-page targets exclude explicit page breaks. When section word counts provide a reasonable split and no section dominates the source, generation plans a break directly before the chosen section heading. This prevents a continued-list branch from consuming the next section's entries and causing repetition. Long sections retain internal breaks between closed entry lists, and unheaded employment/education retains flexible pagination. Preflight rejects repeated or reversed recognized sections, trailing or misplaced planned breaks, missing or crossed closures, and unsupported sections before compilation. Compiled page counts still enforce the target and two-page maximum; a physical mismatch releases an estimated section boundary for the single repair. Unambiguous dated employment and education records constrain literal Abey subheadings to the correct employer/institution, dates, role/degree and unknown-location arguments; ambiguous records retain flexible macros. Final instructions repeat these source-derived headers, useful inline links, the page target and original academic grades, and require unknown entry fields to stay empty.

Abey heading and item macros are scoped to their corresponding lists during decoding and checked again in preflight. Heading lists and item lists require their first entry immediately after the opening macro, so an Education or Project entry cannot emit a bare LaTeX item outside a list and empty Abey lists cannot reach compilation. A required second page starts with `\vspace*{24pt}` after the page break so its first heading has top padding.

The centered header scopes the large small-caps name font inside braces, then resets to normal size after its line break. Oversized name styles are unavailable as free body commands, and preflight rejects ungrouped name font switches that would enlarge the contact row.

When every confident employment and education record belongs to one recognized source section, its literal header choices are available only in that section, including across an internal page break. An unrelated Activities section cannot select a known employment header. Ambiguous and unheaded sources retain flexible decoding; independent factual validation remains required.

The model cannot add packages, redefine the layout, or introduce fonts outside the cached template dependencies. Hyperlink destinations are constrained to original source links and matching email/phone contacts, with LaTeX escapes supplied in the prompt and enforced during generation and repair. The separate factual audit uses its JSON schema instead of the LaTeX grammar.

The template uses standard LaTeX line semantics so its aligned entries work: source newlines are whitespace, blank lines or `\par` end paragraphs, and `\\` ends a header or skills row. Entry columns wrap long titles. The Tectonic adaptation removes pdfTeX-only glyph setup and unused graphics dependencies, uses `fontawesome5` alone, and keeps bullet glyphs at readable size. The compiler warmup reads the actual template preamble and exercises its font shapes, icons and entry macros. Startup compiles that trusted probe through the same offline container entrypoint, permissions, memory and file limits used for candidate documents, including when restoring a cached image. An unusable compiler fails before model generation. Template changes invalidate the compiler image and Actions dependency cache. Verify offline compilation and layout with `RESUME_COMPILER_INTEGRATION=true node --test test/resumeLatexLayout.test.js` after runtime setup.

Before publication, PDF.js inspects and renders every page. Readable text, minimum 10pt size, page boundaries, identity, contacts, employer/title/date associations, education, numbers, skills, and link destinations are checked. Academic grades remain protected when moved between the institution and degree rows; ambiguous education groups keep their original grade-containing anchors. A separate model call audits factual support. One repair is allowed; a failed repair preserves the previous successful version. Repair feedback omits an unchanged canonical preamble already present in the original prompt, retaining all candidate content while reserving context for the correction. The container reduces common TeX errors to fixed categories (alignment, commands, math delimiters, braces, environments and lists), giving the repair specific guidance without exporting compiler logs. Public diagnostics contain fixed codes, reasons and counts only.

The Actions job allows 30 minutes. The worker's 28-minute deadline starts at the first workflow step, includes dependency setup, and leaves time for cleanup and saving immutable dependencies. Generation uses the remaining deadline rather than a separate eight-minute request cutoff, reserving up to three minutes for PDF compilation and factual validation. The single repair shares that generation deadline. Cold downloads and compilation warmup can take several minutes. Model weights, the verified runtime archive, and the trusted compiler image are cached; candidate documents and model responses are excluded from caches.

During inference, the worker polls the local model once per minute for bounded numeric input, processed-prompt and output token counters. Progress requests time out after at most five seconds and stop with the model request. Missing telemetry does not fail generation. Slot prompts and settings are never forwarded to diagnostics.

Both base and tailored documents use the original page count: one-page inputs produce one page, two-page inputs produce two pages, and longer inputs are condensed to two pages. PDF extraction records the actual page count; DOCX extraction retains a saved page count when available. For unpaginated TeX or Word sources without page metadata, the worker allows one or two readable pages. The AI plans content and spacing within that budget, condenses repeated wording, and uses moderate section/entry spacing and natural page breaks without filler, blank pages, reduced margins or text below 10pt. The compiled PDF must meet its required page count before the factual audit or publication; one correction is allowed. Protected employment, education, contact and numerical facts remain checked. The application has no monthly Actions run cap. The existing allowance of ten tailoring requests per user per UTC day remains.

Existing `source-template:` generations are marked stale and require a fresh AI preparation or tailoring request. Their stored artifacts remain in revision history.

New worker output records style `abey-resume-v1`. Regenerate an existing resume to apply this template; stored PDF and TeX revisions retain their original bytes.

Install and verify the runtime on Linux x64 with Docker available, then run the real synthetic model/LaTeX/PDF benchmark:

```sh
npm run resume:setup
npm run resume:benchmark -- --output .cache/ai-resume-benchmark
```

These commands load no environment file or live database, process only synthetic data, and write QA documents beneath `.cache/`. The worker installs the same pinned dependencies automatically on an Actions cache miss. Model and runtime identities are recorded in `resume-model.json`; compiler identities and warmed dependencies are in `compiler/`.

`sourceTemplate.js` and `sourceTemplatePipeline.js` remain synthetic fixture helpers with licensed bundled fonts. They are not a generation fallback in the application worker. `benchmarkSourceResumes.js` exercises those helpers and source extraction separately from AI quality and compilation.
