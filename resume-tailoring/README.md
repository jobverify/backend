# AI resume preparation and tailoring

The active worker in `resumePipeline.js` runs the pinned Qwen3-4B-Instruct-2507 Q4_K_M model locally with llama.cpp. It reads the original document, entered or confirmed profile evidence, and the actual Abey template code in `templates/abey-resume.tex`, then generates a complete candidate LaTeX document using that template. Tailoring also supplies the prepared base LaTeX and the saved job's candidate-facing requirements. The selected Abey format takes precedence over a legacy base document's layout. Supported experience can be rewritten, selected, and ordered for the job; job requirements never become unsupported candidate claims.

Generated LaTeX passes a strict preflight and is compiled into the published PDF by Tectonic inside an isolated Docker container. Compilation has no network, host mounts, credentials, writable root filesystem, or shell escape. The PDF and downloadable TeX come from the same validated generated document. Abey's letter geometry, centered contact header, ruled sections and resume entry macros are preserved, with readable text alongside its contact icons. Useful links appear inline with contacts, projects, activities or certifications. The worker never appends a Links section or generic Original link labels; new output containing them is sent for repair. Unused annotation-only references and mismatched placeholder contacts may be omitted, while visible contact and profile destinations remain protected.

LaTeX decoding is constrained to the Abey preamble and supported document commands in `src/utils/resumeLatexFormat.js`. Preparation and repair receive the full template as formatting code; its sample content is never candidate evidence. The model fills the body using the template macros and cannot add packages, redefine the layout, or introduce fonts outside the cached template dependencies. New worker output must retain the exact preamble and centered header; generic legacy layouts remain readable but are rejected as new output. Hyperlink destinations are constrained to original source links and matching email/phone contacts, with LaTeX escapes supplied in the prompt and enforced during both generation and repair. The separate factual audit uses its JSON schema instead of the LaTeX grammar.

The template uses standard LaTeX line semantics so its aligned entries work: source newlines are whitespace, blank lines or `\par` end paragraphs, and `\\` ends a header or skills row. Entry columns wrap long titles. The Tectonic adaptation removes pdfTeX-only glyph setup and unused graphics dependencies, uses `fontawesome5` alone, and keeps bullet glyphs at readable size. The compiler warmup reads the actual template preamble and exercises its font shapes, icons and entry macros. Template changes invalidate the compiler image and Actions dependency cache. Verify offline compilation and layout with `RESUME_COMPILER_INTEGRATION=true node --test test/resumeLatexLayout.test.js` after runtime setup.

Before publication, PDF.js inspects and renders every page. Readable text, minimum 10pt size, page boundaries, identity, contacts, employer/title/date associations, education, numbers, skills, and link destinations are checked. A separate model call audits factual support. One repair is allowed; a failed repair preserves the previous successful version. Repair feedback omits an unchanged canonical preamble already present in the original prompt, retaining all candidate content while reserving context for the correction. Public diagnostics contain fixed codes and counts only.

The Actions job allows 30 minutes. The worker's 28-minute deadline starts at the first workflow step, includes dependency setup, and leaves time for cleanup and saving immutable dependencies. Generation uses the remaining deadline rather than a separate eight-minute request cutoff, reserving up to three minutes for PDF compilation and factual validation. The single repair shares that generation deadline. Cold downloads and compilation warmup can take several minutes. Model weights, the verified runtime archive, and the trusted compiler image are cached; candidate documents and model responses are excluded from caches.

Both base and tailored documents use the original page count: one-page inputs produce one page, two-page inputs produce two pages, and longer inputs are condensed to two pages. PDF extraction records the actual page count; DOCX extraction retains a saved page count when available. For unpaginated TeX or Word sources without page metadata, the worker allows one or two readable pages. The AI plans content and spacing within that budget, condenses repeated wording, and uses moderate section/entry spacing and natural page breaks without filler, blank pages, reduced margins or text below 10pt. The compiled PDF must meet its required page count before the factual audit or publication; one correction is allowed. Protected employment, education, contact and numerical facts remain checked. The application has no monthly Actions run cap. The existing allowance of ten tailoring requests per user per UTC day remains.

Existing `source-template:` generations are marked stale and require a fresh AI preparation or tailoring request. Their stored artifacts remain in revision history.

New worker output records style `abey-resume-v1`. Regenerate an existing resume to apply this template; stored PDF and TeX revisions retain their original bytes.

Install and verify the runtime on Linux x64 with Docker available, then run the real synthetic model/LaTeX/PDF benchmark:

```sh
npm run resume:setup
npm run resume:benchmark -- --output .cache/ai-resume-benchmark
```

These commands load no environment file or live database, process only synthetic data, and write QA documents beneath `.cache/`. The worker installs the same pinned dependencies automatically on an Actions cache miss. Model and runtime identities are recorded in `resume-model.json`; compiler identities and warmed dependencies are in `compiler/`.

`sourceTemplate.js` and `sourceTemplatePipeline.js` remain synthetic fixture helpers with licensed bundled fonts. They are not a generation fallback in the application worker. `benchmarkSourceResumes.js` exercises those helpers and source extraction separately from AI quality and compilation.
